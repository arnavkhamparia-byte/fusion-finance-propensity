FIELD DEFINITIONS:

borrower_confirmed — true if agent spoke to the actual registered borrower
third_party_answered — true if someone OTHER than the borrower picked up
third_party_type — relationship of the third party to the borrower (null if borrower answered)
  - Family Member Picked Up: spouse, parent, sibling, child, relative
  - Friend Or Neighbour Picked Up: friend or neighbour answered
  - Do Not Know Borrower: person denies knowing borrower / wrong number (live person answered)
  - Borrower Died: third party informs borrower has passed away

payment_intent — true if customer expressed ANY willingness to pay (with or without a date)
  A partial amount with a relative date counts fully: "Main 2000 bhej deta hoon, teen din baad" → payment_intent=true
intent_strength:
  - high: firm, confident language ("zaroor dunga", "pakka", "bilkul karunga")
  - low: vague or hesitant ("dekhta hoon", "koshish karunga", "shayad")
  - none: no payment intent at all
specific_date_mentioned — YYYY-MM-DD only if customer committed to a SPECIFIC payment date
  Resolve relative dates: "kal" → current_date+1, "agle hafte" → current_date+7, "15 tarikh" → 15th of current or next month,
  "N din baad" → current_date+N; range ("do-chaar din baad", "2-4 din mein") → use the EARLIEST bound (current_date+2)
amount_mentioned — plain numeric string if any payment amount was discussed ("5000" not "Rs 5000")

sm_call_agreed — true if customer agreed to speak with senior manager
sm_call_reason — why customer agreed to SM call:
  - For Settlement Discussion: settlement / waiver / reduced amount
  - For Other Payment Plan: EMI restructuring, installments
  - For Further Loan Details: questions about loan, interest, breakup
  - Other: agreed but reason unclear

callback_requested — true ONLY if BORROWER explicitly gave a SPECIFIC time/day for Rohini to call back
  Hour-based requests count: "ek ghante baad call karna", "do ghante baad phone karo" → callback_requested=true
  Vague deferrals ("sochta hoon", "dekhta hoon", "bata doonga") do NOT count
callback_datetime — ISO 8601 with IST offset if callback was explicitly requested, else null
  Resolve: "shaam" → 17:00, "subah" → 10:00, no time + same day → current_time+2h, future day → 09:00
  Relative: "N ghante baad" → current_time+N hours, "N minute baad" → current_time+N minutes, "N din baad" → current_date+N days; range → earliest bound

payment_claimed — true if customer claims payment was ALREADY made (to agent, field worker, or directly)
payment_claimed_type: Full Payment / Partial Payment / Not Sure Of Amount

dispute_detected — true if borrower disputes the loan's EXISTENCE or VALIDITY (not just the amount while acknowledging the loan)
dispute_type:
  - Not Availed Loan: "yeh loan maine nahi liya"
  - Already Cleared The Loan: "maine sab de diya tha" (angry, frustrated)
  - Amount Disputed: interest/outstanding calculation challenged
  - Fraud Claim: identity theft / someone else used their credentials
  - Insurance Claim Related: loan covered by insurance

hardship_detected — true if borrower disclosed an ACTIVE, ONGOING personal or financial crisis
hardship_type: Medical Issue / Job Loss / Business Loss / Agriculture Loss / Death In Family / Other
hardship_soft_signal — true if distress signals present WITHOUT explicit verbal statement:
  - Customer clearly crying or unable to speak
  - Heavy phrases: "sab kuch khatam ho gaya", "kuch nahi bacha", "bahut bura waqt"
  - Background sounds: crying child, commotion, family crisis sounds
  - Customer disoriented or deeply overwhelmed without stating reason

settlement_negotiated — true if agent and customer actively discussed specific settlement amounts (agent pitched a number, customer responded)
settlement_outcome: only when settlement_negotiated is true:
  - Needs Lower Settlement Amount: customer gave a specific counter-amount
  - Did Not Agree For Settlement: customer engaged but declined without counter-offer
  - Other: engaged but outcome doesn't fit above

abrupt_disconnect — true if call ended ABRUPTLY before any natural conclusion:
  SET TRUE:
    - Line went dead mid-sentence or mid-conversation with no warning
    - Customer hung up immediately (within seconds of connecting) without meaningful exchange
    - Call dropped due to network failure mid-conversation
    - Agent said "main kaata hoon" / "phir call karta hoon" because audio was completely one-sided
    - Customer cut the call after 1-2 words with no outcome ("haan" then line dead)
  SET FALSE:
    - Agent said any form of goodbye or closing ("theek hai", "phir baat karte hain", "okay") — even if no outcome was reached
    - Call went to voicemail
    - Conversation fizzled out after some exchange and agent ended it
  KEY: Was there ANY natural closing from either side? If yes → false. If the call just STOPPED → true.
voicemail_detected — true if call hit voicemail system
no_answer — true if phone rang but no one answered and no voicemail
busy_signal — true if phone was busy at telecom level
call_failed — true if call failed to connect at telecom level
invalid_number — true if number is unreachable at telecom level (switched off, not in service, number does not exist) — NOT for wrong numbers answered by live persons
disconnected_immediately — true if call connected briefly then dropped with zero exchange

promise_made — true if customer explicitly committed to paying by a SPECIFIC date
  A partial amount + resolvable relative date IS a real promise: "Main 2000 bhej deta hoon, teen din baad" →
  promise_made=true, specific_date_mentioned=current_date+3, amount_mentioned="2000".
  An amount smaller than the full EMI does NOT weaken the promise.
commitment_strength — calibrate carefully against these anchors:
  - strong:   customer gave a SPECIFIC DATE and/or AMOUNT with confident language
              ("kal de dunga", "15 tarikh ko 5000 deta hoon", "pakka kar diya", "zaroor dunga")
  - moderate: customer expressed CLEAR WILLINGNESS but no date/amount
              ("haan dunga", "karunga payment", "try karunga", agreed to SM call cooperatively)
  - weak:     customer was HESITANT or NON-COMMITTAL
              ("dekhta hoon", "koshish karunga", "shayad", "abhi nahi ho sakta")
  - none:     NO payment intent at all — customer was passive, refused, disputed, or was a third party
              (Third Party Connect, Dispute, Refuse To Pay, Information Conveyed, Call Hung Up, Unclear with zero intent)
tone_shift: improved (started resistant, ended cooperative) / neutral / worsened
call_sentiment: positive (cooperative, hopeful) / negative (hostile, angry) / neutral (flat, passive)
engagement_level:
  - high: asked questions, discussed options, cooperative
  - medium: responded but largely passive
  - low: monosyllabic, evasive, barely participated
type_of_customer: Co-operative / Neutral / Non Co-operative
network_quality: Excellent (crystal clear) / Good (mostly clear) / Poor (frequent drops/distortion)
conversation_quality: Excellent (full protocol, empathetic) / Good (mostly well-handled) / Poor (skipped steps, robotic)
customer_attributes — array, select ALL that apply: "Soft Spoken", "Abusive", "Straight Forward", "Cunning", "Fearful", "Fearless"
compliance_violation — true if AGENT (not customer) committed a violation: threats of arrest/police/violence, harassment, false statements, abusive language by agent, calling outside hours, disclosing loan details to third party
compliance_type: Legal / RBI / Police / Other (null when no violation)
immediate_callback_needed — true if situation warrants same-day follow-up
summary — factual English summary, max 500 characters, no line breaks

DISAMBIGUATION RULES (CRITICAL):

Third Party vs Borrower — THE MOST CRITICAL DISAMBIGUATION:

DEFAULT RULE: third_party_answered=false, borrower_confirmed=true UNLESS you have CLEAR evidence a stranger answered.

SET third_party_answered=true ONLY when:
  - Person explicitly says they are NOT the borrower: "main [borrower name] nahi hoon", "yeh number galat hai", "yahan koi [name] nahi rehta"
  - Person says a DIFFERENT name when asked who they are
  - Person says borrower is unavailable / has passed away / doesn't live there

KEEP third_party_answered=false (borrower IS on the line) when:
  - Person uses FIRST-PERSON about the loan: "mera loan nahi hai", "maine nahi liya", "mera koi account nahi", "main nahi dunga" — THESE ARE THE BORROWER
  - Person is angry, aggressive, or uncooperative — uncooperative ≠ third party
  - Person denies the loan exists — DISPUTE, not third party
  - Person's identity is ambiguous — DEFAULT TO BORROWER
  - Person says very little before hanging up — DEFAULT TO BORROWER

FIRST-PERSON RULE: If the person uses "mera", "maine", "main", "mujhe", "humara" about the loan or debt → they ARE the borrower. Always. No exception.

Payment Claimed vs Dispute:
- payment_claimed=true: customer believes payment WAS made, wants it acknowledged ("maine de diya tha")
- dispute_detected=true: customer contests loan EXISTENCE or VALIDITY ("maine loan hi nahi liya")
- If both signals present: set both true

Abrupt Disconnect vs Natural End:
- abrupt_disconnect=true: line went dead, call dropped mid-conversation, customer cut call deliberately, agent said "main kaata hoon" due to bad audio
- abrupt_disconnect=false: conversation ended naturally, agent said goodbye, call fizzled out

Hardship Soft Signals:
- Do NOT require explicit hardship statement
- Crying, background chaos, "sab kuch khatam ho gaya" → hardship_soft_signal=true

Callback vs Deferral:
- callback_requested=true ONLY for specific time: "kal shaam 5 baje", "kal call karo", "2 din baad", "ek ghante baad"
- "Sochta hoon", "Dekhta hoon", "Bata doonga" = deferral, NOT callback_requested

OUTPUT ONLY THE JSON OBJECT. NOTHING ELSE.
